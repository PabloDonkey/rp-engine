### **S030 · 2026-08-12 · Scenario form editor — read and edit a scenario without JSON** — the panel's scenario pages were a `<pre>` dump and a raw-JSON `<textarea>`. The detail page is now one card per part, in **prompt order** (description → opening → world → character → rules, the order `ConversationBuilder` assembles), and the edit page is a sectioned form. JSON dropped back to the two edges: an **Import** button that takes several files at once, and Export. `POST /admin/scenarios/import` had existed since S010 with **nothing calling it**. **Two problems the review turned up, both fixed.** (1) *The metadata type was a lie* — five types declared `dict[str, str]` while curated scenarios stored a `tags` array, and it survived only because the loader never checked and the column is JSONB. `core/metadata.py` now holds `str | list[str]` in one place, with a normalizer that coerces a scalar (`1987` → `"1987"`), drops a null, and **fails the whole payload** on a nested shape. (2) *Scenarios could not be retired* — soft delete landed with the invariant that makes it safe: **`save()` never writes `deleted_at`**, because the boot import saves every catalog file at every start and would otherwise resurrect what you retired. `/play` refuses a retired scenario with the same reply as an unknown id, and stories already running it keep playing. Migration `20260811_0013`, reversible both ways against a real Postgres. Also: `count_live_by_definition()` (one grouped query, not one per row), `DELETE`/`restore` routes, a **show retired** checkbox off by default, and a retire dialog that names the live session count before it asks. **The frontend got its first test runner** — Vitest 4 in browser mode with Playwright and headless Chromium, 59 tests. Vitest 4 needed `browser.instances` and a fifth package (`@vitest/browser-playwright`) the epic did not know about. Writing the tests found **two real bugs**: `MetadataField` deleted the row you were typing, because its model watcher rebuilt from its own echo and a "we are writing" flag cannot span two ticks; and `ScenarioForm` used `structuredClone`, which throws on a Vue reactive proxy. ⚠️ **Four live checks are open** (browser, Telegram, restart, file round trip). → [archive](archive/S030-2026-08-12-scenario-form-editor.md) · [design](https://claude.ai/code/artifact/fda5b259-2e76-4491-8346-79923b0d880d) · [S010](archive/S010-2026-07-26-admin-scenario-catalog-mgmt.md)

### **S029 · 2026-08-11 · Memory window status, and running the summary by hand** — the admin panel now answers "when is the next recap due?" instead of only "what does the recap say?". The session page gained two bars — the window against the fold line, and the recap against its own share — plus the counts behind them: budget, window tokens, messages held versus stored, turns covered, turns ready to fold, and turns that left the window uncovered. **The first live run found two real problems, both fixed here.** The first gauge measured the window against the fold line — which sits at full forever, because folding a turn does not delete it — and the engine was folding on nearly every turn once a story passed the line, one model call each. Layer 01 now folds in **batches** (`RP_ENGINE_MEMORY_SUMMARY_MIN_FOLD_SHARE`, 10% of the budget, and never larger than the slack the fold line leaves), and the panel shows the story as three parts that add up to the whole of it: in the recap, waiting to fold, replayed word for word. The gauge next to it is the batch filling and emptying, which is what the window bar wrongly implied. A **Run summary now** button runs the same pass the background worker runs after a turn. It runs **inline**, because a queued job would return at once and tell the operator nothing, and it works even when the layer is switched off for that session, so a recap can be read before deciding to switch it on. `RollingSummaryStatus` is a read-only twin of the first half of `observe` — the same walk, the same marks — so the panel and the worker cannot disagree about what is due. The composition root now builds one `RollingSummarySource` and shares it between the pipeline and the panel. One read serves the whole panel: `GET /admin/sessions/{id}/memory` replaced the narrower summary endpoint from S023. No table, no migration, no change to the turn path. ⚠️ **The live panel check is open.** → [archive](archive/S029-2026-08-11-memory-window-status-and-manual-summary-run.md) · [S023](archive/S023-2026-08-10-memory-layer-01-rolling-summary.md)

### **S023 · 2026-08-10 · Memory layer 01 — the rolling summary, and the background worker** — the engine keeps a running "story so far". What falls past **75%** of the context budget is condensed into one recap, the recap is condensed again when it outgrows its own **quarter** of the budget, and it reaches every prompt as a `[Story So Far]` block ranked directly below the window. Landed with it: the **background worker** S021 designed and nothing had built — in-process `asyncio.Queue`, one job per session, bounded, cancelled (not drained) on shutdown, every failure logged and swallowed; `ChatService` submits one question per finished turn and waits for nothing. `session_summaries` + migration `20260810_0012`, reversible both ways against a real Postgres; per-source **budget shares** on `MemorySettings` (S022 cut them as YAGNI, this is the second source that needed them); `/memory summary on|off`; an admin switch that also shows the stored recap and how far it reaches. **`LMStudioConversationSummarizer` is wired into the composition root for the first time**, its character-handoff prompt replaced by two rolling-recap prompts. **One deliberate deviation from ADR-026:** `MemoryObserveContext` gained `memory_budget` and `source_budget`, filled in by the pipeline when the job *runs* — rule 3 keeps the budget with the pipeline, and the worker needs both numbers. The test that matters most: **dropping the job entirely leaves the next turn writing the same recap**, which is the property the whole no-durability design rests on. Layer 01 is **on by default**; a session saved between S022 and S023 reads as an explicit opt-out and needs one `/memory summary on`. ⚠️ **Three live runs still open** (past the window boundary, the toggle, and a restart mid-job), alongside S022's. → [archive](archive/S023-2026-08-10-memory-layer-01-rolling-summary.md) · [ADR-026](../docs/adr/0026-layered-memory.md) · [MEMORY.md](../docs/MEMORY.md)
